# 04 开发计划

状态:草案 v0.1(2026-10-16)。产品文档中里程碑「时间待排期」,本文给出排期草案,启动 M1 时由项目负责人确认并填入实际日期。

## 1. 原则

- 5 个里程碑,每个必须通过验收才进入下一个
- P0 先于 P1:M1–M3 完成即得到可上车的最小版本
- 每个里程碑结束:打 tag、更新文档中的「待验证」项、记录内存与帧率基线
- 实车测试尽早做:M2 起带上车,不要等到 M3

## 2. 里程碑总览

排期假设:1 人业余时间投入(每周约 10–15 小时)。全职投入可按 1/3 估算。

| 里程碑 | 目标 | 周期草案 | 累计 |
| --- | --- | --- | --- |
| M1 平台跑通 | Brookesia chatbot 示例在 Tab5 上运行,小智能对话 | 3–4 周 | 第 4 周 |
| M2 系统壳 | Launcher、状态栏、设置、音频焦点、音乐 App、MCP 工具 | 4–5 周 | 第 9 周 |
| M3 导航 P0 | Unit GPS、离线瓦片地图、定位跟随、骑行统计 | 3–4 周 | 第 13 周 |
| M4 体验补齐 P1 | 路线转向播报、在线规划、电台、小游戏、BLE、OTA | 6–8 周 | 第 21 周 |
| M5 扩展 P2 | 日夜自动切换、骑行数据卡片、摄像头 | 视情况 | — |

M3 完成约在第 13 周,即可得到「P0 最小可上车版本」。排期不含硬件采购、支架 / 防水壳设计,这部分与 M1–M2 并行(见第 4 节)。

## 5. 验收标准汇总

| 对象 | 验收 |
| --- | --- |
| M1 | 屏幕版本确认;热点下 10 轮对话无异常 |
| M2 | 语音打开 App / 切歌 / 调音量;音乐中可唤醒;小智说话音乐压低 |
| M3 | 骑行 30 分钟定位不丢、地图不卡 |
| M4 | 路线转向语音正确;在线规划可用且失败有回退;BLE 按键可控音乐与唤醒;OTA 成功且失败可回滚;游戏骑行中被拒绝 |
| 全程 | 启动 ≤ 5s / 可唤醒 ≤ 10s;滑动 ≥ 30fps、地图 ≥ 20fps;断网时本地功能正常 |

## 6. 工作方式

- 分支:`main` 保持可构建;功能分支 `feat/<模块>`;每个里程碑结束合并并打 tag `m1`…`m5`
- 提交信息:英文,祈使句,带需求编号,如 `navi: parse GGA/RMC (NAV-01)`
- 周节奏:每周一次小结,更新本文任务状态与风险登记
- 变更:需求或架构变更先改文档 / 写 ADR,再改代码
