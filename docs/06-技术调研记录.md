## 2. 详细依据

### 2.1 Tab5 硬件(T1、T3、T7、T8、T12、T16)

[文档] Tab5 规格(M5Stack 文档):

- SoC:ESP32-P4,双核 RISC-V 360 MHz + 低功耗核 40 MHz;Flash 16MB;PSRAM 32MB
- 无线:ESP32-C6-MINI-1U(Wi-Fi 6),经 SDIO2 接 P4;内置天线 + 2 个 MMCX 外接天线口,射频开关选内 / 外置
- 屏幕:5 英寸 IPS 1280×720,MIPI-DSI;背光 G22
- 触摸:GT911(地址 0x14)或 ST7123 / ST7121 集成(地址 0x55),取决于版本;I2C 为 G31 (SDA) / G32 (SCL),与编解码器、IMU、RTC、电量计、IO 扩展器共线
- 音频:ES8388 播放(0x10)+ ES7210 采集(0x40),双麦,AEC;功放 NS4150B,1W @ 8Ω,由 `SPK_EN` 控制;3.5mm 耳机口,带插入检测
- 存储:microSD,G39–G44
- 摄像头:SC2356 200 万像素 MIPI-CSI
- 接口:USB-A 主机、USB-C OTG;RS-485;HY2.0-4P `PORT.A`(黑 GND、红 5V、黄 G53、白 G54);M5-Bus 30 针;侧面 2.54-10P 扩展口
- 电源:NP-F550 可拆电池 7.4V 2000mAh(14.8Wh);INA226 电量计(0x41);USB-C 充电
- 其它:BMI270 IMU、RX8130CE RTC、两颗 PI4IOE5V6408 IO 扩展器(控制屏幕 / 触摸 / 摄像头复位、扬声器使能、耳机检测、5V 总线使能、充电)
- 尺寸 128.0 × 80.0 × 12.0 mm,120.9 g;侧面 1/4″-20 三脚架螺孔
- **工作温度 0–40 °C**

[文档] 屏幕驱动时间线:2025-05-09 首发(ILI9881C + GT911);2025-10-14 换为集成 ST7123;2026-04-28 换为 ST7121。通过机身背面贴纸识别。

[文档] 电池与充电:官方续航约 6 小时(50% 亮度、Wi-Fi 开、后台任务);**设备开机后才能充电,关机不充**;电池电压低于 6V 进入保护模式,需要取下电池、复位、装回后再充。

[文档] 页面写明 `EXT_5V_BUS` 给 M5-Bus、侧面扩展口和 HY2.0-4P 供 5V,可由 `EXT5V_EN` 控制;未给最大电流。

[文档] Unit GPS v1.1(U032-V11):AT6668(ATGM336H-6N 模组),GPS / QZSS / BDS(B1I+B1C)/ Galileo / GLONASS,50 通道;UART 115200 8N1;最高 10Hz;冷启动 23 秒,热启动 1 秒;5V,31.64mA;内置陶瓷天线;页面未写工作温度。

[待核] 线序:M5 页面的引脚图文字有误,按其列表顺序推断为 黑 GND、红 5V、黄 UART_RX、白 UART_TX。若成立,对应 Tab5:G53 做 UART TX(接 GPS RX),G54 做 UART RX(接 GPS TX)。以原理图为准,首次上电前用万用表或逻辑分析仪确认,避免把 5V 接到信号脚。

[待核] 改波特率 / 刷新率:M5 页面只指向 CASIC 协议手册,没有给命令。AT6668 / ATGM336H 系列通常用 `$PCAS` 系列语句,但需对照协议手册核实后再写入固件。

[推算] 备选串口:`PORT.C`(M5-Bus 上的 G6 / G7,标为 PC_TX / PC_RX)和 `RXD0 / TXD0`(G38 / G37)也能做 UART,但走背部 M5-Bus,车把安装不方便,仅作后备。

**对设计的影响**

1. 产品文档里的「Grove 口」统一改称 `PORT.A`。
2. 固件必须先通过 IO 扩展器打开 `EXT5V_EN`,GPS 才有电;GPS 5V 开关属于电源管理,放进板级初始化。
3. 工作温度上限 40°C 与「夏季暴晒」场景直接冲突,下限 0°C 限制冬季骑行,见风险 R11。
4. 低电量保护:电池低于 6V 要走特殊恢复流程,固件应在远高于 6V 时就提示并安全关机,具体阈值用 INA226 实测电池曲线后定。
5. 「关机不充电」意味着骑行结束后设备需要开机插线才会充,充电提示要在 UI 中明确。

### 2.2 板级定义与 Board Manager(T2、T13、T16)

[文档] `espressif/m5stack_boards` 最新 0.6.1~2,是 ESP Board Manager 的 M5Stack 板级定义集合,其中包含 **M5Stack Tab5**:ES8388(DAC)+ ES7210(ADC)、SDMMC、MIPI-DSI LCD、I2C 触摸、MIPI-CSI 摄像头。0.5.1 起默认配置包含 ST7121 面板 / 触摸变体,以及 P4 芯片版本选项(`CONFIG_ESP32P4_SELECTS_REV_LESS_V3`、`CONFIG_ESP32P4_REV_MIN_100`)。

[文档] `m5stack_boards ≥0.6.0` 要求 `esp_board_manager ≥0.7.1`。该组件不是 `esp_board_manager` 的默认依赖,需在工程里显式添加。

[文档] `brookesia_hal_boards 0.8.0` 依赖 `esp_board_manager 0.5.*`;其板卡列表(Espressif:`esp32_p4_function_ev`、`esp32_p4x_function_ev`、`esp32_s3_korvo2_v3`、`esp_box_3`、`esp_sensair_shuttle`、`esp_vocat_board_v1_0/v1_2`、`esp32_s31_korvo1`、`esp_mosaico_v1_0/v1_2`;另有 Waveshare、RYMCU 板)**不含 M5Stack Tab5**。

[推算] 因此 Brookesia 路线需要:新增一个 Tab5 板级条目,结构参照现有板(每块板一个目录,含 `board_info.yaml`、`board_devices.yaml`、`board_peripherals.yaml`、`sdkconfig.defaults.board`、可选 `setup_device.c`),设备参数从 `m5stack_boards` 的 Tab5 配置迁移。需要先解决 T13 的版本冲突,可选做法:(a) 工程内使用 `m5stack_boards 0.5.x` 配合 `esp_board_manager 0.5.*`(原产品文档引用的即是 0.5.4);(b) 把 Tab5 条目作为本项目的本地板级组件,不依赖 `m5stack_boards`;M1 先试 (a),不通就用 (b)。

[文档] 回退路径可行:`78/xiaozhi-esp32` 的 `main/boards/m5stack/` 下有 `tab5` 目录;该项目要求 **ESP-IDF ≥ 6.0.1(推荐 6.1)**,不支持 5.x;支持端侧 MCP(扬声器、LED、舵机、GPIO 等)。

### 2.3 Brookesia 现状(T2、T10、T11)

[文档] 自 v0.7 起 Brookesia 组件化,各组件独立演进但共享 major.minor 版本,并依赖同一 IDF 版本:

| 分支 | 状态 | ESP-IDF |
| --- | --- | --- |
| master(v0.8) | 活跃开发,新增 PC 仿真、JSON UI、多 runtime、System Super | 6.0 – 6.2 |
| release/v0.7 | 稳定,只修 bug 和安全问题 | 5.5 – 6.0 |
| release/v0.6 | 已停止维护 | 5.3 – 5.5 |

另有要求:Flash ≥8MB,PSRAM ≥4MB(chatbot 示例要求 Flash ≥16MB、PSRAM ≥8MB、支持 Wi-Fi,并有 AudioCodecPlayer / Recorder、DisplayPanel / Touch、StorageFs 接口)。

[文档] 旧单体 `espressif/esp-brookesia 0.5.0`(Phone 系统 UI)依赖 LVGL 9.2.*,IDF ≥5.3,已不是当前主线。

[文档] 当前组件(均 v0.8.x):

| 层 | 组件 |
| --- | --- |
| 工具 | `brookesia_lib_utils`(任务调度、线程配置、性能分析、日志、状态机、插件) |
| 服务框架 | `brookesia_service_manager`(插件式生命周期、线程安全本地调用、事件发布订阅)、`brookesia_service_helper` |
| 服务 | `service_wifi`(状态机、扫描、连接、SoftAP)、`service_audio`(播放、编解码、音量、AFE:VAD + WakeNet)、`service_device`(音量 / 亮度 / 静音等设备控制)、`service_display`、`service_storage`、`service_nvs`、`service_sntp` |

| GUI | `brookesia_gui_interface`、`brookesia_gui_lvgl` |
| 系统 | `brookesia_system_core`(native / runtime App 安装与生命周期、App 作用域的 GUI / 存储 / 定时器)、`brookesia_system_super`(桌面、状态栏、App Launcher、overlay)、`brookesia_app_settings` / `app_store` / `app_files` |

[文档] `brookesia_agent_xiaozhi` 的 MCP 能力:`AddMCP_ToolsWithServiceFunction`(把已有服务函数注册为 MCP 工具)、`AddMCP_ToolsWithCustomFunction`(自定义工具)、`RemoveMCP_Tools`。chatbot 示例里小智已可通过 MCP 调亮度、音量、静音、电量、拍照等。默认半双工:Agent 说话时不听,但可被唤醒词打断。唤醒词配置默认留空,表示由 Audio 服务自动识别。

[文档] System Super 示例板卡列表为 `esp32_p4x_function_ev`、`esp32_s31_korvo1`、`esp_mosaico_v1_0/v1_2`;默认集成 Display / Audio / Wi-Fi / HTTP / Storage / SNTP / Video / Device 服务、Coze 与小智 Agent、LVGL 后端、JS runtime,预装 Settings、App Store、Files。有 SD 卡的板可把 SD 卡当外部存储卷。

[待核] 注册表对 System Super 的描述是「handheld square-screen system shell」,README 描述为「面向矩形触摸设备的标准系统」。1280×720 横屏是否有现成样式不确定(旧版 Phone 系统有 1280×800、720×1280 样式,可作参考)。若不适配,退路是用 `service_manager + gui_lvgl + agent_xiaozhi` 自己做 Launcher,仍保留服务和 Agent 层。

**结论**:路线 A 仍成立,但落地方式从「Brookesia Phone + App」改为「Brookesia 服务层 + 小智 Agent + System Super 或自研 Launcher」。IDF 选 **v6.0.x(≥6.0.1)**:它同时满足 v0.7(≤6.0)、v0.8(≥6.0)和 xiaozhi-esp32(≥6.0.1)。详见 ADR-0002。

### 2.4 离线地图与路线(T4、T5)

[文档] `0015/map_tiles 2.0.0`(2026-09-25):MIT;依赖 IDF ≥5.0、LVGL ≥9.3.0;目标含 ESP32-P4。同一组件两套 API:

- v1(`map_tiles.h`):固定格网的 `lv_image`,同步在 UI 线程加载,适合手拖查看
- v2(`map_view.h`、`map_route.h`、`map_tile_cache.h`、`map_geo.h`):连续坐标、平滑拖动带惯性、LRU 缓存 + 后台读卡线程、未命中先画占位图、`route.bin` 路线与地图匹配、转向提示、偏航检测、跟随模式与偏移量

[文档] v2 对 PSRAM 实际上是必需:单块解码瓦片 128KB;466px 视图需约 25–28 槽(3–3.5MB),720px 视图需 48 槽(6MB)。

[文档] 瓦片格式:`{base_path}/{folder}/{zoom}/{tile_x}/{tile_y}.bin`,12 字节头 + 256×256 RGB565 原始像素。

[文档] `map_route_match()` 每次定位返回:是否在路线上、横向偏差、吸附点与路线方位、已行 / 剩余距离、下一机动点索引与距离、是否到达、是否绕圈、回归点与方位。偏航时进度冻结。`route.bin` 每点 16 字节、每转向 20 字节,10000 点约 160KB;每点带 `min_zoom` 字节做按缩放级别的抽稀。路线分 DRIVE / EXERCISE 两种,闭环支持圈数统计。`map_view_set_position(map, lat, lon, heading, ...)` 带航向;文档里**没有**地图随航向旋转的接口。

[文档] 官方配套 PC 工具 `0015/OfflineMapDownloader`(MIT):`app_nav.py`(端口 5001)沿路线走廊下载瓦片、转成 RGB565 `.bin`,生成 `navigation_sdcard.zip`,含 `tiles1/<z>/<x>/<y>.bin`、`routes/*.bin`、`routes/*.txt`;路由用 OSRM(驾车)和 Valhalla(步行、**骑行**、驾车);也可 `route_format.py --gpx ride.gpx --out route.bin` 从 GPX 生成;支持「回到起点」闭环。示例:对角线路线、缩放 15–17、走廊 300m,约 850 块瓦片,而包围盒需约 4300 块。

[文档] 数据源与授权:v1 直连公共 OSM / Esri 端点,仅限个人、教育、实验用途,不得大批量自动下载;**v2 不允许从公共 OSM 服务器构建**,只提供条款允许离线使用的数据源(如 Geoapify 免费档),并把署名写入 SD 卡。

[推算] 容量:一块瓦片 12 + 131072 = 131084 字节 ≈ 128KiB,每 1000 块约 128MiB;示例走廊 850 块约 106MiB。32GB 卡理论可容纳约 20 万块以上,但每提高一级缩放,同一区域的瓦片数约 ×4。

[推算] 我们地图视图约 1160×672(含 Dock)至 1280×672(全屏导航):同时可见瓦片约 6×4 = 24 块,加预取环约 8×6 = 48 块,所以 6MB(48 槽)是下限,需要时放大到 8MB(64 槽)。组件说明「缓存放不下环加屏幕时会静默停止预取」,要在 M3 用实测确认槽数。

[推算] 地图旋转:PPA 的 SRM(缩放 / 旋转 / 镜像)最低吞吐在 IDF 测试里是 P4 芯片版本 <v3 约 21 Mpx/s,v3 及以上约 35 Mpx/s。地图层按 1160×672 ≈ 0.78 Mpx 计,仅旋转一项就约 22–37ms / 帧,上限约 27–45 fps,再加上 LVGL 其余绘制就不宽裕。因此 **P0 做北向上 + 航向标记旋转;「跟随车头」转图作为 M3 后半的实验项**,达不到 20 fps 就只保留旋转标记。

### 2.5 语音(T6、T7、T15)

[文档] ESP-SR 的 WakeNet9 / 9l 适用于 ESP32 / S3 / P4。「你好小智」模型有:`wn9_nihaoxiaozhi_tts`、`wn9l_nihaoxiaozhi_tts3`、`wn9s_nihaoxiaozhi`、`wn10_nihaoxiaozhi`、`wn10_nihaoxiaozhi_int16`;另有定制唤醒词服务。官方提示:大多数模型由 TTS 流水线生成,泛化能力不能完全保证,商用前需在目标环境充分评估。检测阈值可调(`set_wakenet_threshold`,esp-sr ≥2.1.3)。

[文档] AFE 可同时做 VAD、双麦增强、AEC、WakeNet;P4 / S3 使用更大模型并保留完整前端,抗噪好于 C 系列。最多同时加载两个唤醒词。

[文档] Brookesia chatbot 示例要求唤醒词模型已烧入 `model` 分区,否则唤醒无响应。

[文档] Brookesia `service_audio`:URL 播放(单个或播放列表,本地 LittleFS 或网络),暂停 / 恢复 / 停止,PCM / OPUS / G711A 编解码,AFE(VAD + WakeNet)事件;v0.7.6 起音量归 `service_device` 管。

[待核] SD 卡路径与 MP3 / AAC / FLAC 是否经该服务直接支持,文档没有明说。备选是直接用 `esp_audio_codec` / `esp_audio_simple_player` 一类组件自建音乐播放链路,再把「音频焦点」与 AFE 的 AEC 参考打通。

[文档] 扬声器功放 NS4150B 为 1W @ 8Ω,骑行风噪下可能不够响。**建议备选**:3.5mm 耳机口外接小功率有源扬声器或单耳耳机(注意骑行安全法规与路况),此项属于我的建议,不是资料结论。

### 2.6 联网与 BLE(T14)

[文档] P4 通过 `esp_hosted`(推荐 ≥2.4.2)+ `esp_wifi_remote`(≥1.0.0)用 C6 提供 Wi-Fi;menuconfig 选 `Wi-Fi Remote → slave target = esp32c6`;C6 需运行 ESP-Hosted 协处理器固件;`esp_hosted` 曾以明文传输 Wi-Fi 凭据,在意的话可选 `eppp` 方案。官方文档建议主机组件版本升级跨度大时同步升级从机固件。

[文档] BLE:控制器在 C6,P4 跑主机栈;官方有 NimBLE over Hosted HCI 与 Wi-Fi 共存示例(`bleprph_wifi_coex`);Bluedroid 也有对应配置(`esp_hosted_bt_controller_init` 等)。

[文档] C6 固件 OTA:经 ESP-Hosted 现有总线升级,无需额外硬件;三种来源(HTTPS、LittleFS 分区、原始 `slave_fw` 分区);会先比较版本;从机固件 ≥v2.6.0 时有 `OTA_ACTIVATE` 步骤;升级完成后**主机需要重启**以避免同步问题。

[待核] Tab5 出厂 C6 固件版本与最新 `esp_hosted` 主机端的兼容性(版本差距大时需先升级从机)。M1 第一步读版本。

### 2.7 显示性能(T5 相关)

[文档] ESP32-P4 MIPI-DSI 在 LVGL v9.4 benchmark 下:1024×600 RGB565 约 55 fps(占用 PSRAM 3.7MB);800×1280 约 40 fps(6.0MB);RGB565 与 RGB888 相比 RGB565 更快。`esp_lvgl_adapter` 提供防撕裂(三缓冲 partial 等)、PPA 加速、JPEG / PNG 硬解码,但版本为 `0.1.0-beta.1`;启用 PPA 时 `LV_DRAW_SW_DRAW_UNIT_CNT` 应为 1,且 PPA 通常降低 CPU 占用而不明显提升 FPS。

[文档] 推荐 P4 配置:`CONFIG_CACHE_L2_CACHE_256KB=y`、`CONFIG_CACHE_L2_CACHE_LINE_128B=y`、`CONFIG_SPIRAM_XIP_FROM_PSRAM=y`、`CONFIG_COMPILER_OPTIMIZATION_PERF=y`、`CONFIG_FREERTOS_HZ=1000`、`CONFIG_LV_DEF_REFR_PERIOD=15`。

[推算] 1280×720 像素数约为 1024×600 的 1.5 倍,桌面 / 列表帧率估计在 35–45 fps 区间,满足「桌面滑动 ≥30fps」,但要实测。RGB565 帧缓冲 1280×720×2 = 1,843,200 字节 ≈ 1.76MiB,与产品文档「2×1.8MB」一致。

### 2.8 在线路径规划(T9)

[文档] 高德 Web 服务:`GET https://restapi.amap.com/v4/direction/bicycling`,必填 `key`、`origin`、`destination`(经度,纬度,小数不超过 6 位);支持最长 500km 的骑行路线;响应 `data.paths[]`(`distance`、`duration`、`steps[]`),每步有 `instruction`、`distance`、`polyline`(`X,Y;X1,Y1;...`)、`road`、`orientation`、`duration`、`action`、`assistant_action`;`errcode=0` 为成功。个人开发者的日配额和 QPS 页面没写,需查流量页(`/api/webservice/guide/tools/flowlevel`)。

[推算] 高德使用 GCJ-02 坐标(行业常识,上述文档页没有明示,M4 时对照官方坐标系说明核实),而 GPS 和 OSM 瓦片是 WGS-84。如果直接把折线画在 OSM 瓦片上会有数十到数百米偏移。需要在端侧加 GCJ-02 → WGS-84 转换(迭代反解,误差为米级),或改用 Valhalla 等输出 WGS-84 的规划服务。

[设计] 端侧在线规划:拿到折线和步骤后,在设备上生成 `route.bin`(需把 `route_format.py` 的写入逻辑用 C 实现,含 `min_zoom` 抽稀和转向表),写入 SD 卡后用 `map_route_load()` 加载;这样在线与离线路径走同一条渲染 / 匹配 / 播报链路。`map_route.h` 中的精确二进制布局在 M4 开工时对照头文件确认。

接口抽象:`RoutePlanner` 有两个后端(高德、Valhalla / 自建),设置页可切换。
