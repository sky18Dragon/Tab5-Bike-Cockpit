# ADR-0004 工具链基线改为 ESP-IDF v5.5.3 + Brookesia v0.7(取代 ADR-0002 的 IDF 选择)

- 状态:已接受(2026-10-19)
- 关系:取代 ADR-0002 中「ESP-IDF 固定 v6.0.x」的决定;ADR-0002 其余内容(组件化 Brookesia、锁版本、M1 末做桌面壳选择)继续有效,ADR-0001 不变

## 背景

M1 开工后在真实依赖上做了一次完整的配置和编译,发现 ADR-0002 的前提不成立。

事实(均来自实际构建输出和组件源码):

1. Tab5 的 ESP32-P4 是 **rev < v3**。`esp_board_manager` 自带的 Tab5 板级配置里就是 `CONFIG_ESP32P4_SELECTS_REV_LESS_V3=y`、`CONFIG_ESP32P4_REV_MIN_100=y`。
2. `esp-sr 2.4.4`(唤醒词与 AFE 所需)的 `CMakeLists.txt` 明确写了:rev<v3 且 IDF 主版本 ≥6 时 `FATAL_ERROR`,提示「ESP-SR only support ESP32P4 rev less v3 on ESP-IDF v5.5 or earlier」。在 IDF 6.0.2 上对 Tab5 配置会直接停在 CMake 阶段。
3. Brookesia v0.8 这一组把 `esp-sr` 锁死在 2.4.4:`brookesia_hal_adaptor` / `service_audio` → `jason-mao/av_processor`(要求 `gmf_ai_audio ^0.8.3`)→ `gmf_ai_audio 0.8.3`(精确依赖 `esp-sr 2.4.4`)。所以在 v0.8 上无法靠升级 `esp-sr` 绕开。
4. `esp-sr` 的 master 分支已经出现 `esp32p4_less_v3_idf6` 的库路径,说明上游在补这个缺口;但已发布的 2.4.5–2.6.0 是否带这套库,我没有核实。
5. Brookesia v0.7 这一组在 IDF 5.5.3 上依赖解析、配置和板级生成全部通过(`esp_hosted 2.12.3`、`esp_wifi_remote 1.6.5`、`esp_lvgl_adapter 0.5.3`、LVGL 9.6.0~1、`esp-sr 2.4.4`、`esp_board_manager 0.5.15`)。原产品设计文档引用的也是 v0.7.4 的 chatbot 示例。

## 备选

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. IDF 5.5.3 + Brookesia 0.7.x | 厂商验证过的 rev<v3 组合 | **采用** |
| B. IDF 6.0.x + Brookesia 0.8 + 本地改 `gmf_ai_audio` 放宽 `esp-sr` 版本 | 要用到未核实的 `less_v3_idf6` 库,音频前端出问题难定位 | 不采用,待 `esp-sr` 发布稳定版后再评估 |
| C. IDF 6.x + 换成 rev≥v3 的 P4 硬件 | 不适用于 Tab5 | 不适用 |

## 决策

- ESP-IDF 固定 **v5.5.3**
- Brookesia 全部组件固定 **0.7.\***(`brookesia_hal_boards 0.7.5`、`hal_adaptor 0.7.4`、`agent_xiaozhi 0.7.4`、`service_audio 0.7.7` 等),`esp_lvgl_adapter 0.5.*`
- 板级:本项目自带 `firmware/boards/m5stack_tab5`(以 `esp_board_manager` 自带 Tab5 为基线改成 Brookesia 0.7 的配置),用 `idf.py gen-bmgr-config -c ./boards -b m5stack_tab5` 生成
- 桌面壳:System Super 只在 v0.8 里,所以本项目 M2 起自研 Launcher(即 ADR-0002 的方案 A2),服务层和 Agent 层沿用 Brookesia

## 后果

- ADR-0002 里「M1 同时试 System Super」不再适用,T10 改为「自研 Launcher 的工作量评估」
- 回退路线 `xiaozhi-esp32` 要求 IDF ≥6.0.1,在 rev<v3 上是否可用同样取决于 `esp-sr` 对 IDF 6 的支持,不再算作无条件可用的回退
- IDF 5.5.x 的生命周期较 6.x 短;跟踪 `esp-sr` 的 `esp32p4_less_v3_idf6` 何时进入正式版,届时重新评估升级到 IDF 6
- 本机已装 IDF 5.5.3(`~/esp/esp-idf-v5.5.3`)和 6.0.2(`~/.espressif/v6.0.2`),切换环境靠各自的 `export.sh` / `activate_idf_*.sh`
