# ADR-0002 工具链与版本基线:ESP-IDF 6.0.x + Brookesia 组件化(补充 ADR-0001)

- 状态:已接受(2026-10-16)
- 关系:补充 ADR-0001,不取代;ADR-0001 的「路线 A」仍然成立,本条明确它在当前版本下如何落地

## 背景

ADR-0001 写成时,按旧单体 `esp-brookesia`(Phone 系统 UI,v0.5.0)理解路线 A。调研发现 Brookesia 已重构:

- v0.7 起组件化,各组件版本同步演进;master(v0.8)要求 IDF 6.0–6.2,release/v0.7 要求 IDF 5.5–6.0
- 旧 Phone 系统不是当前主线;桌面壳变成 System Super(v0.8 新增)
- 小智 Agent 变成独立组件 `brookesia_agent_xiaozhi`(基于 `esp_xiaozhi`),MCP 经 `brookesia_mcp_utils`
- Tab5 不在 `brookesia_hal_boards` 里;在 `m5stack_boards`(ESP Board Manager)里
- `xiaozhi-esp32` 要求 IDF ≥6.0.1,且已有 `m5stack/tab5` 板级目录

## 备选

| 方案 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A1. IDF 6.0.x + Brookesia v0.8(master) | 用 System Super,服务与 Agent 全部同一版本链 | 有现成桌面壳、Settings;与 xiaozhi ≥6.0.1 一致 | master 可能不稳定;System Super 对 1280×720 横屏的支持待核 |
| A2. IDF 6.0.x + Brookesia release/v0.7 | 稳定分支,只用服务层与 Agent,自研 Launcher | 稳定;范围小 | 没有 System Super;仍要自研桌面 |
| A3. IDF 5.5 + Brookesia v0.7 | | 工具链较旧但成熟 | 与 xiaozhi 回退路线(≥6.0.1)不兼容,回退要换 IDF |

## 决策

- ESP-IDF 固定 **v6.0.x(≥6.0.1)**,同时兼容 A1、A2 与回退路线 B
- Brookesia 在 M1 先用 v0.7 稳定分支验证 chatbot 示例;并行试 v0.8 的 System Super 示例(T10)。两者都能在 IDF 6.0.x 上构建
- M1 末做版本选择:System Super 能满足 Dock + 卡片 + 1280×720 横屏,就走 A1;否则走 A2 并自研 Launcher
- 所有组件版本在 `idf_component.yml` 与 `dependencies.lock` 中锁定

## 后果

- 需要新增 Tab5 板级条目,并解决 `esp_board_manager` 版本冲突(T13)
- 需要核对 LVGL 版本满足 `map_tiles ≥9.3.0`(T11)
- 升级 Brookesia 跨 minor 版本时,按破坏性变更处理,单独评估
- 回退线不变:M1 内适配超过 2 周未稳定,回退到 `xiaozhi-esp32` 的 Tab5 固件,另写 ADR 取代 ADR-0001
