# ADR-0001 选用 ESP-Brookesia 作系统框架,小智 Agent 作语音助手

- 状态:已接受(2026-10-16)
- 决策者:项目负责人

## 背景

需要一个能管理多个独立功能(导航、音乐、游戏、设置)、带桌面和语音助手的系统框架,运行在 Tab5(ESP32-P4)上。产品文档把此选择称为「路线 A」。

## 备选

| 方案 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. ESP-Brookesia + 内置小智 Agent | Espressif 的系统框架,App 生命周期、Launcher、服务框架、chatbot 示例 | 贴合「每个功能是一个 App、以 MCP 工具暴露给小智」的设计;框架层现成 | Tab5 不在官方示例板列表,需适配;API 迭代快 |
| B. xiaozhi-esp32 的 Tab5 固件 + 自己补 Launcher | 社区固件,已支持 Tab5 | 起步快、板级已适配 | 需自己做 App 管理和桌面;架构约束少但要自己搭 |
| C. 完全自研 | LVGL + 自己的 App 管理 | 完全可控 | 工作量最大,重复造轮子 |

## 决策

选 A。理由:与产品设计(应用化、MCP 工具、后台 App、事件通信)直接对应,框架层不必自研。

## 后果

- 需要为 Tab5 适配板级定义(基于 `m5stack_boards`),M1 的首要任务
- 锁定 Brookesia、m5stack_boards、map_tiles 组件版本,升级前单独评估
- **回退条件**:M1 内适配超过 2 周仍无法稳定运行,回退到 B,并新增 ADR 取代本条;代码尽量把 App 逻辑与框架解耦(业务放服务层和 `bike_*` 组件),降低回退成本
