# 07 M1 进展:平台跑通

日期:2026-10-19。分支:`feat/m1-platform-bringup`。

## 一句话结论

**M1 的编译基线已经完成,实机验证没有做。** 固件能在 IDF 5.5.3 + Brookesia 0.7.x 下为 Tab5 完整编译出来,「你好小智」唤醒词模型已打进固件。开发机上没有接 Tab5(没有 USB 串口设备),所以显示、触摸、音频、唤醒、联网、小智对话全部**未实测**,M1 的验收标准(热点下连续对话 10 轮)还没达成。

| 项 | 结果 |

## 构建时发现的、改变了原计划的事

1. **IDF 6 对 Tab5 不可用。** `esp-sr 2.4.4` 在 rev<v3 的 P4 + IDF 6 上直接 `FATAL_ERROR`;Brookesia v0.8 又把 `esp-sr` 锁在 2.4.4。所以基线从 ADR-0002 的「IDF 6.0.x」改为「IDF 5.5.3 + Brookesia 0.7.x」(ADR-0004)。
2. **System Super 用不了。** 它只在 v0.8,Launcher 要自研。
3. **屏幕原生是竖屏 720×1280。** 当前固件以竖屏出画面;横屏是示例 `display.cpp` 里的一个旋转参数,留到有实机再做(T17)。
4. **固件偏大。** 6.13MiB,16MB Flash 放不下两个 OTA 分区,OTA 之前要瘦身(T19)。
5. **Tab5 板级其实是现成的。** `esp_board_manager` 自带 `m5stack_tab5`,GPS 的 5V(`EXT5V_EN`)在板级初始化里默认打开,ESP-Hosted 的 SDIO 引脚也已由它给出并与此前的推断一致。

## 接上 Tab5 之后的验证清单

按顺序做,每一步通过再进下一步。

```bash
cd firmware
./build.sh flash /dev/cu.usbmodemXXXX
```

- [ ] 能烧录,串口能看到启动日志(控制台走 USB Serial/JTAG)
- [ ] 日志里出现 `Tab5 panel variant: ST7121`,屏幕点亮,画面方向为竖屏
- [ ] 触摸有响应(ST7121 触摸地址 0x55)
- [ ] 启动日志里没有 PSRAM / 看门狗 / 栈溢出报错;记录启动耗时和 `free heap`(内部 / PSRAM)
- [ ] 扬声器出声(激活码语音或提示音),`SPK_EN` 生效
- [ ] 录音:对着麦克风说话,日志里看到 AFE / VAD 事件
- [ ] Wi-Fi:首次开机进入配网热点,用手机配网;C6 联网成功。若失败,先读 C6 固件版本并按 ESP-Hosted 文档升级从机固件
- [ ] 小智激活(激活码语音 + 官方激活流程)
- [ ] 说「你好小智」可唤醒;与小智连续对话 10 轮无异常(M1 验收)
- [ ] 记录结果回填本文和 06 的 T16–T19

失败时的排查入口:

| 现象 | 先看 |
| --- | --- |
| 黑屏但有背光 | 日志里的面板变体;`esp_lcd_st7121` 在 RGB565 下的初始化(板级里把 24 位改成了 16 位,这是最大的未验证改动) |
| 触摸无响应 | 触摸地址探测日志;`TP_RST` / `TP_INT` 时序 |
| 无声音 | `SPK_EN`(IO 扩展器 0x43 的 P1);I2S 引脚;ES8388 初始化日志 |
| 唤醒不灵 | ES7210 通道标签与 `MIC_LAYOUT`(T18);唤醒阈值 |
| Wi-Fi 连不上 | C6 固件与 `esp_hosted` 版本;SDIO 引脚日志 |

## 风险提示

- 板级把 ST7121 / ST7123 的帧格式从上游的 RGB888 改成 RGB565,是为了配合 Brookesia 0.7 的 HAL 适配器(其他 P4 板都是 RGB565)。读了 `esp_lcd_st7121` 的源码:驱动本身不读 `bits_per_pixel`,像素格式由 DPI 配置(`in_color_format: RGB565`)决定,所以 16 位路径有可能直接可用,但是否点得亮、颜色是否正确只能实机验证。如果不行,回退办法是把 `setup_device.c` 里的覆盖去掉(恢复上游的 24 位和单帧缓冲),同时把适配层改成 RGB888。
- 以上编译结果证明「依赖能解析、代码能链接」,不证明「功能能用」。
